Aufgabe 04b

Gekoppelte Inputs mit @bind

🎯 Lernziel

Du löst dieselbe Aufgabe wie in 04, aber mit @bind + @bind:event="oninput" in beiden Inputs. Beide schreiben automatisch in dieselbe value-Variable – kein manueller Sync nötig.

🔧 Konzepte

<input type="range"> <input type="number"> @bind:event="oninput" @bind:after [Parameter] Min/Max/Step EventCallback<decimal>

📋 Aufgabe

  1. 1. Erstelle DualInput.razor mit Slider und Number-Input.
  2. 2. Binde beide Inputs an dieselbe decimal value mit @bind + @bind:event="oninput".
  3. 3. Nutze @bind:after für den EventCallback – ein Lambda reicht.
  4. 4. Füge [Parameter] für Min, Max, Step hinzu.
  5. 5. Zeige den Wert in Prozent-Format ("42,5 %") an.

📌 Der Unterschied zu 04

In 04 hast du zwei separate Handler HandleSlider und HandleNumber gebraucht. Hier reicht @bind – beide Inputs schreiben automatisch in value, @bind:after feuert den Callback. Kein manuelles Sync, kein Math.Round.

💡 Hinweise – Code-Schnipsel

Der Kern der Lösung:

// Beide Inputs, ein @bind:after:
[Parameter]
public EventCallback<decimal> OnValueChanged { get; set; }

<input type="range" @bind="value"
       @bind:event="oninput"
       @bind:after="() => OnValueChanged.InvokeAsync(value)" />

<input type="number" @bind="value"
       @bind:event="oninput"
       @bind:after="() => OnValueChanged.InvokeAsync(value)" />

@code {
    private decimal value = 50;

    [Parameter] public decimal Min { get; set; } = 0;
    [Parameter] public decimal Max { get; set; } = 100;
    [Parameter] public decimal Step { get; set; } = 1;
}

💡 @bind aktualisiert value automatisch bei jeder Eingabe – egal ob Slider oder Number.Field.

💡 Der Callback feuert bei beiden Inputs, weil jedes @bind:after hat.

🔧 Teil-Lösung – Code-Gerüst

Ergänze die ❌-Stellen:

@* DualInput.razor *@

<div>
    <input type="range" @bind="value"
           @bind:event="oninput" ❌ />
    <span>@value.ToString("F1") %</span>
    <input type="number" @bind="value"
           @bind:event="oninput" ❌ />
</div>

@code {
    [Parameter]
    public EventCallback<decimal> OnValueChanged { get; set; }

    [Parameter] public decimal Min { get; set; } = 0;
    [Parameter] public decimal Max { get; set; } = 100;
    [Parameter] public decimal Step { get; set; } = 1;

    private decimal value = 50;
}

📌 Fehlend: Jeweils @bind:after="() => OnValueChanged.InvokeAsync(value)" in beiden Inputs.

🏁 Vollständige Lösung 
@* DualInput.razor *@

<div class="d-flex align-items-center gap-3">
    <input type="range" class="form-range flex-grow-1"
           @bind="value" @bind:event="oninput"
           @bind:after="() => OnValueChanged.InvokeAsync(value)"
           min="@Min" max="@Max" step="@Step" />

    <span class="fw-bold text-primary min-w-64 text-center">
        @value.ToString("F1", CultureInfo.InvariantCulture) %
    </span>

    <input type="number" class="form-control w-25"
           @bind="value" @bind:event="oninput"
           @bind:after="() => OnValueChanged.InvokeAsync(value)"
           min="@Min" max="@Max" step="@Step" />
</div>

@code {
    [Parameter]
    public EventCallback<decimal> OnValueChanged { get; set; }

    [Parameter] public decimal Min { get; set; } = 0;
    [Parameter] public decimal Max { get; set; } = 100;
    [Parameter] public decimal Step { get; set; } = 0.5m;

    private decimal value = 50;
}

💡 Tipps

  • Da beide Inputs dieselbe value binden, sind sie automatisch synchron – kein manuelles oninput nötig.
  • @bind:event="oninput" ist wichtig für den Slider, damit er flüssig reagiert.
  • Der @bind:after-Callback feuert bei beiden Inputs – du musst ihn nicht duplizieren, es reicht dasselbe Lambda.

✅ Akzeptanzkriterien

  • Slider und Number-Feld sind jederzeit synchron
  • Slider reagiert flüssig auf Ziehen
  • Number-Feld akzeptiert präzise Werteingabe
  • Die Anzeige zeigt den Wert in Prozent-Format
  • Es wird @bind + @bind:event="oninput" + @bind:after verwendet
