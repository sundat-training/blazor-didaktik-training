Aufgabe 02b

Gekaskadete Selects mit @bind

🎯 Lernziel

Du löst dieselbe Aufgabe wie in 02a, aber mit @bind und @bind:after in beiden Child-Komponenten. Du siehst, wie konsequenter @bind-Einsatz den Code in jeder Komponente schlanker macht.

🔧 Konzepte

[Parameter] EventCallback<T> Parent→Child Datenfluss Dictionary<K,V> @bind @bind:after @key

📋 Aufgabe

  1. 1. Erstelle zwei Komponenten: CategorySelect.razor (Kategorie-Auswahl) und ItemSelect.razor (Item-Auswahl).
  2. 2. CategorySelect gibt die gewählte Kategorie per EventCallback<string> nach oben – nutze @bind:after.
  3. 3. ItemSelect nimmt per [Parameter] eine Liste von Items entgegen und zeigt sie im Dropdown an – auch hier @bind:after.
  4. 4. Erstelle eine Parent-Seite, die beide Komponenten einbettet. Bei Kategorie-Wechsel wird die Item-Liste neu gesetzt.
  5. 5. Verwende ein Dictionary<string, List<string>> als Datenquelle.
  6. 6. Sorge dafür, dass bei Kategorie-Wechsel die Item-Auswahl zurückgesetzt wird.

📌 Der Unterschied zu 02a

In 02a nutzen beide Childs @onchange + value + ChangeEventArgs. Hier setzen beide auf @bind + @bind:after mit Inline-Lambda – weniger Boilerplate pro Komponente, gleiche Schnittstelle nach außen.

💡 Hinweise – Code-Schnipsel

Die wichtigsten Bausteine:

// CategorySelect mit @bind:after:
<select @bind="selectedCategory"
        @bind:after="() => OnCategoryChanged.InvokeAsync(selectedCategory)">
    ...
</select>

// ItemSelect mit @bind:after + Disabled:
<select @bind="selectedItem"
        @bind:after="() => OnItemSelected.InvokeAsync(selectedItem)"
        disabled="@Disabled">
    ...
</select>

// Parent bleibt gleich:
<CategorySelect OnCategoryChanged="HandleCategoryChanged" />
<ItemSelect Items="@currentItems" OnItemSelected="HandleItemSelected"
            Disabled="@string.IsNullOrEmpty(selectedCategory)"
            @key="@selectedCategory" />

💡 Die EventCallback-Schnittstelle ändert sich nicht – nur die interne Implementierung der Childs wird schlanker.

🔧 Teil-Lösung – Code-Gerüst

Ergänze die ❌-Stellen in beiden Child-Komponenten:

@* CategorySelect.razor *@

<select class="form-select" @bind="selectedCategory" ❌>
    <option value="" disabled selected>Bitte wählen...</option>
    @foreach (var cat in categories)
    {
        <option value="@cat">@cat</option>
    }
</select>

@code {
    [Parameter]
    public EventCallback<string> OnCategoryChanged { get; set; }

    private string selectedCategory = "";
    private string[] categories = { "Ordinary", "Compressed", "Moon", "Compressed Moon" };
}
@* ItemSelect.razor *@

<select class="form-select" @bind="selectedItem" ❌
        disabled="@Disabled">
    <option value="" disabled selected>Bitte wählen...</option>
    @foreach (var item in Items)
    {
        <option value="@item">@item</option>
    }
</select>

@code {
    [Parameter]
    public List<string> Items { get; set; } = new();
    [Parameter]
    public bool Disabled { get; set; }
    [Parameter]
    public EventCallback<string> OnItemSelected { get; set; }

    private string selectedItem = "";
}

📌 Fehlend: Jeweils @bind:after="() => On...InvokeAsync(...)" im <select>.

🏁 Vollständige Lösung 
@* CategorySelect.razor *@

<div class="mb-3">
    <label class="form-label fw-bold">Kategorie</label>
    <select class="form-select" @bind="selectedCategory"
            @bind:after="() => OnCategoryChanged.InvokeAsync(selectedCategory)">
        <option value="" disabled selected>Bitte wählen...</option>
        @foreach (var cat in categories)
        {
            <option value="@cat">@cat</option>
        }
    </select>
</div>

@code {
    [Parameter]
    public EventCallback<string> OnCategoryChanged { get; set; }

    private string selectedCategory = "";
    private string[] categories = { "Ordinary", "Compressed", "Moon", "Compressed Moon" };
}
@* ItemSelect.razor *@

<div class="mb-3">
    <label class="form-label fw-bold">Item</label>
    <select class="form-select" @bind="selectedItem"
            @bind:after="() => OnItemSelected.InvokeAsync(selectedItem)"
            disabled="@Disabled">
        <option value="" disabled selected>Bitte wählen...</option>
        @foreach (var item in Items)
        {
            <option value="@item">@item</option>
        }
    </select>
</div>

@code {
    [Parameter]
    public List<string> Items { get; set; } = new();

    [Parameter]
    public bool Disabled { get; set; }

    [Parameter]
    public EventCallback<string> OnItemSelected { get; set; }

    private string selectedItem = "";
}

Parent-Seite:

@* CascadingSelectPage.razor *@

<CategorySelect OnCategoryChanged="HandleCategoryChanged" />
<ItemSelect Items="@currentItems" Disabled="@string.IsNullOrEmpty(selectedCategory)"
            OnItemSelected="HandleItemSelected" @key="@selectedCategory" />

@if (selectedItem != null)
{
    <p>Auswahl: @selectedCategory → @selectedItem</p>
}

@code {
    private string selectedCategory = "";
    private string? selectedItem;
    private List<string> currentItems = new();

    private Dictionary<string, List<string>> data = new()
    {
        ["Ordinary"] = new() { "Veldspar", "Scordite", "Pyroxeres", "Plagioclase" },
        ["Compressed"] = new() { "Compressed Veldspar", "Compressed Scordite" },
    };

    private async Task HandleCategoryChanged(string category)
    {
        selectedCategory = category;
        currentItems = data.GetValueOrDefault(category, new());
        selectedItem = null;
    }

    private void HandleItemSelected(string item)
    {
        selectedItem = item;
        Console.WriteLine($"Item: {item}");
    }
}

💡 Tipps

  • Die Parent-Seite bleibt identisch zu 02a – nur die Childs werden mit @bind schlanker.
  • @bind:after feuert nach jeder Aktualisierung – auch bei leerer Auswahl. Das ist hier OK, weil der Parent ohnehin auf gültige Werte reagiert.
  • @key auf ItemSelect sorgt dafür, dass Blazor die Komponente bei Kategorie-Wechsel neu aufbaut und der interne State (selectedItem) zurückgesetzt wird.
  • Vergleiche die Code-Menge von CategorySelect in 02a vs. 02b – ~50% weniger.

✅ Akzeptanzkriterien

  • Kategorie-Dropdown zeigt alle Kategorien an
  • Item-Dropdown zeigt nur Items der gewählten Kategorie
  • Bei Kategorie-Wechsel wird die Item-Auswahl zurückgesetzt
  • Item-Dropdown ist deaktiviert, solange keine Kategorie gewählt ist
  • Die Auswahl beider Dropdowns wird auf der Seite angezeigt
  • Beide Childs verwenden @bind + @bind:after – kein manuelles @onchange
