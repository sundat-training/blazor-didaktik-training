Einführung 01

Select: Umsetzen einer simplen Select-Komponente

🎯 Ziel dieser Aufgabe

Du baust eine Blazor-Komponente mit einem <select>-Dropdown. Das klingt simpel – aber in Blazor läuft Datenbindung anders als in reinem HTML/JS. Probiere unten das fertige Verhalten aus, dann setzt du es in Blazor um.

🔍 Das Beispiel zum Ausprobieren

Wähle eine Kategorie aus dem Dropdown. Die Auswahl wird sofort angezeigt – genau dieses Verhalten soll deine Blazor-Komponente später haben.

📖 Was passiert hier?

Reines HTML + JavaScript:

<!-- Das HTML -->
<select id="demoSelect">
    <option value="" disabled selected>Bitte wählen...</option>
    <option value="Ordinary">Ordinary</option>
    <option value="Compressed">Compressed</option>
    <option value="Moon">Moon</option>
    <option value="Compressed Moon">Compressed Moon</option>
</select>
<p id="demoOutput"></p>

<!-- Das JavaScript -->
<script>
document.getElementById('demoSelect')
    .addEventListener('change', function(e) {
        var output = document.getElementById('demoOutput');
        output.textContent = e.target.value
            ? 'Gewählt: ' + e.target.value
            : '';
    });
</script>

Problem: In Blazor gibt es kein document.getElementById und kein direktes DOM-Manipulation. Du musst Datenbindung nutzen: @bind oder @onchange + value. Das DOM wird von Blazor für dich verwaltet.

🧩 Übertragung nach Blazor

Aus dem HTML/JS wird in Blazor:

  • HTML-Teil → bleibt fast gleich, nur id und JS-Events entfallen
  • e.target.value → wird zu @bind oder ChangeEventArgs
  • textContent setzen → wird zu einer Variable, die Blazor automatisch rendert
  • EventListener → wird zu @onchange (manuell) oder @bind + @bind:after

Das Ziel: Dieselbe Benutzererfahrung – aber ohne DOM-API, nur mit Blazor-Datenbindung.

💡 Bevor du loslegst

  • Spiele mit dem Demo-Dropdown oben – das ist das Soll-Verhalten.
  • Überlege: Wie würdest du "Auswahl speichern und anzeigen" ohne DOM-API umsetzen?
  • Dann geht's weiter mit Aufgabe 01a (manuell) oder Aufgabe 01b (@bind).
