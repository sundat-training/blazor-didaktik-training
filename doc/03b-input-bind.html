Aufgabe 03b

Input mit Validierung & @bind

🎯 Lernziel

Du löst dieselbe Aufgabe wie in 03, aber mit @bind + @bind:event="oninput" + @bind:after. Du siehst, wie @bind auch bei Live-Validierung mit oninput funktioniert.

🔧 Konzepte

<input type="number"> @bind @bind:event="oninput" @bind:after long.TryParse Conditional Rendering EventCallback<long>

📋 Aufgabe

  1. 1. Erstelle QuantityInput.razor mit <input type="number">.
  2. 2. Binde den Input mit @bind="rawValue" @bind:event="oninput". Bei jeder Eingabe wird rawValue aktualisiert.
  3. 3. Validiere in @bind:after="Validate": parse mit long.TryParse(), setze Error-String bei Ungültigkeit.
  4. 4. Zeige den Error-String per Conditional Rendering.
  5. 5. Feuere EventCallback<long> nur bei gültigem Wert.
  6. 6. Füge [Parameter] bool Disabled und [Parameter] long MinValue hinzu.

📌 Der Unterschied zu 03

In 03 nutzt du @oninput="HandleInput" + ChangeEventArgs. Hier übernimmt @bind das Auslesen des Werts – @bind:after ruft die Validierung auf. Kein manuelles e.Value?.ToString(), kein separates value=.

💡 Hinweise – Code-Schnipsel

Die wichtigsten Bausteine:

// @bind + @bind:event + @bind:after:
[Parameter]
public EventCallback<long> OnQuantityChanged { get; set; }

<input type="number"
       class="form-control @(errorMessage != null ? "is-invalid" : "")"
       @bind="rawValue"
       @bind:event="oninput"
       @bind:after="Validate"
       disabled="@Disabled" />

@if (errorMessage != null)
{
    <div class="text-danger small">@errorMessage</div>
}

@code {
    private string rawValue = "";
    private string? errorMessage;

    private async Task Validate()
    {
        // rawValue ist hier bereits aktualisiert
        if (string.IsNullOrWhiteSpace(rawValue)) { ... }
        if (!long.TryParse(...)) { ... }
        errorMessage = null;
        await OnQuantityChanged.InvokeAsync(val);
    }
}

💡 @bind:event="oninput" sorgt dafür, dass die Bindung bei jedem Tastendruck aktualisiert wird (nicht erst beim Verlassen des Feldes).

🏁 Vollständige Lösung 
@* QuantityInput.razor *@

<div class="mb-3">
    <label class="form-label fw-bold">@Label</label>
    <input type="number"
           class="form-control @(errorMessage != null ? "is-invalid" : "")"
           @bind="rawValue"
           @bind:event="oninput"
           @bind:after="Validate"
           disabled="@Disabled"
           min="@MinValue" />
    @if (errorMessage != null)
    {
        <div class="text-danger small mt-1">@errorMessage</div>
    }
</div>

@code {
    [Parameter] public string Label { get; set; } = "Menge";
    [Parameter] public long MinValue { get; set; } = 1;
    [Parameter] public bool Disabled { get; set; }
    [Parameter] public EventCallback<long> OnQuantityChanged { get; set; }

    private string rawValue = "";
    private string? errorMessage;

    private async Task Validate()
    {
        if (string.IsNullOrWhiteSpace(rawValue))
        {
            errorMessage = "Feld darf nicht leer sein";
            return;
        }

        if (!long.TryParse(rawValue, NumberStyles.Integer,
            CultureInfo.InvariantCulture, out var val))
        {
            errorMessage = "Bitte eine gültige ganze Zahl eingeben";
            return;
        }

        if (val < MinValue)
        {
            errorMessage = $"Wert muss >= {MinValue} sein";
            return;
        }

        errorMessage = null;
        await OnQuantityChanged.InvokeAsync(val);
    }
}

💡 Tipps

  • @bind:event="oninput" aktualisiert bei jedem Tastendruck – nötig für Live-Validierung.
  • Im Gegensatz zu 03 gibt es kein ChangeEventArgs – der Wert liegt direkt in rawValue.
  • Leeres Feld = Fehler. Entweder du blockierst es oder erlaubst es als "noch nichts eingegeben".

✅ Akzeptanzkriterien

  • Akzeptiert nur positive ganze Zahlen > 0
  • Zeigt eine rote Fehlermeldung bei leerem Feld, 0 oder negativen Werten
  • Blockiert die Weitergabe des Wertes bei ungültiger Eingabe
  • Das Feld kann von außen deaktiviert werden
  • Es wird @bind + @bind:event="oninput" + @bind:after verwendet
