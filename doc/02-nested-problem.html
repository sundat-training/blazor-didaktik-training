02

Gekaskadete Selects: Zwei abhängige Dropdowns

🎯 Ziel dieser Einführung

Du baust zwei <select>-Dropdowns, die voneinander abhängen: Die Auswahl im ersten bestimmt, welche Optionen das zweite anzeigt. Probiere unten das fertige Verhalten aus.

🔍 Das Beispiel zum Ausprobieren

Wähle zuerst eine Kategorie, dann ein Item aus dieser Kategorie.

📖 Was passiert hier?

Reines HTML + JavaScript mit einer Datenstruktur:

// Datenquelle: Jeder Kategorie sind Items zugeordnet
var data = {
    "Ordinary": ["Veldspar", "Scordite", "Pyroxeres", "Plagioclase"],
    "Compressed": ["Compressed Veldspar", "Compressed Scordite"],
    "Moon": ["Bitumens", "Carnotite", "Cobaltite"],
    "Compressed Moon": ["Compressed Bitumens", "Compressed Carnotite"],
};

Problem: In Blazor manipulieren wir kein DOM direkt. Stattdessen:

  • Dropdown 1 meldet die Auswahl per EventCallback an die Parent-Komponente
  • Die Parent-Komponente filtert die Item-Liste und übergibt sie per [Parameter] an Dropdown 2
  • Blazor rendert Dropdown 2 automatisch neu
🧩 Übertragung nach Blazor

Aus zwei HTML-Selects + JS-Event wird in Blazor:

  • Zwei Child-Komponenten: CategorySelect und ItemSelect
  • Eine Parent-Komponente als "Controller", die den State hält und per [Parameter] weitergibt
  • Datenfluss: Kategorie-Auswahl → EventCallback → Parent filtert → Parameter → Item-Select

💡 Bevor du loslegst

  • Spiele mit der Demo – das ist das Soll-Verhalten.
  • Überlege: Wie kommst du von "zwei HTML-Selects + JS" zu "zwei Blazor-Komponenten + Parent"?
  • Dann geht's weiter mit Aufgabe 02a (manuell) oder Aufgabe 02b (@bind).
