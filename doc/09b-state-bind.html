Aufgabe 09b

Component State mit @bind-Value

🎯 Lernziel

Du löst dieselbe Aufgabe wie in 09, aber mit Two-Way-Component-Binding (@bind-Value). Die Parent-Komponente verdrahtet keine EventHandler mehr – @bind schreibt direkt in die Properties.

🔧 Konzepte

@bind-{Property} @bind-Value [Parameter] + EventCallback Two-Way-Component-Binding Parent→Child ohne Handler

📋 Aufgabe

  1. 1. Erstelle eine Seite Calculator.razor – sie ist der "Controller".
  2. 2. Baue die Komponenten ein – aber nutze @bind-Value statt manueller EventCallback-Verdrahtung.
  3. 3. Jede Child-Komponente muss zwei Dinge bereitstellen:
    • Einen [Parameter] für den Wert (z.B. Value, SelectedCategory)
    • Einen EventCallback<T> mit dem Namen {Property}Changed (z.B. ValueChanged)
  4. 4. Der Parent hat keine Handler-Methoden mehr – nur noch Properties und die Berechnungslogik.
  5. 5. Verwende OnParametersSet, um auf Änderungen zu reagieren und das Ergebnis zu berechnen.

📌 Der Unterschied zu 09

In 09 hat der Parent für jedes Child einen Handler (HandleCategoryChanged, HandleQuantityChanged, …). In 09b schreibt @bind-Value direkt ins Property – OnParametersSet triggert die Berechnung automatisch.

💡 Hinweise – @bind-{Property} in der Praxis

So funktioniert Two-Way-Component-Binding:

// Child-Komponente muss bereitstellen:
[Parameter]
public string SelectedCategory { get; set; } = "";

[Parameter]
public EventCallback<string> SelectedCategoryChanged { get; set; }

// Parent nutzt @bind:
<CategorySelect @bind-SelectedCategory="selectedCategory" />

// Blazor erzeugt daraus:
<CategorySelect SelectedCategory="selectedCategory"
                SelectedCategoryChanged="(...) => selectedCategory = ..." />

💡 Der Name des EventCallback muss {Property}Changed lauten – Blazor sucht automatisch danach.

🔧 Vaterlösung – Parent-Seite (Code-Gerüst)

Vergleiche: 09 (manuell) vs. 09b (@bind):

// 09 — manuelle Handler
<CategorySelect OnCategoryChanged="HandleCategory" />
<QuantityInput OnQuantityChanged="HandleQuantity" />
<DualInput OnValueChanged="HandleFee" />

@code {
    private async Task HandleCategory(string c) { selectedCategory = c; Recalc(); }
    private async Task HandleQuantity(long q)  { quantity = q; Recalc(); }
    private async Task HandleFee(decimal f)    { fee = f; Recalc(); }
}

// 09b — @bind schreibt direkt
<CategorySelect @bind-SelectedCategory="selectedCategory" />
<QuantityInput @bind-Value="quantity" />
<DualInput @bind-Value="fee" />

@code {
    protected override void OnParametersSet()
    {
        // Wird nach jeder @bind-Aktualisierung aufgerufen
        Recalc();
    }
}

📌 Voraussetzung: Die Child-Komponenten müssen auf Two-Way-Parameter umgestellt sein. Siehe Hinweis 3.

🏁 Erforderliche Child-Schnittstellen

Jede Child-Komponente braucht zusätzlich zu ihrem bisherigen Code einen Two-Way-Parameter:

// CategorySelect (Aufgabe 02) — erweitert
[Parameter] public string SelectedCategory { get; set; } = "";
[Parameter] public EventCallback<string> SelectedCategoryChanged { get; set; }

// Im Handler: beide Callbacks feuern
await OnCategoryChanged.InvokeAsync(val);
await SelectedCategoryChanged.InvokeAsync(val);

// QuantityInput (Aufgabe 03) — erweitert
[Parameter] public long Value { get; set; }
[Parameter] public EventCallback<long> ValueChanged { get; set; }

// DualInput (Aufgabe 04) — erweitert
[Parameter] public decimal Value { get; set; }
[Parameter] public EventCallback<decimal> ValueChanged { get; set; }

// Parent-Seite Calculator.razor
<CategorySelect @bind-SelectedCategory="selectedCategory" />
<QuantityInput @bind-Value="quantity" />
<DualInput @bind-Value="fee" />

@code {
    private string selectedCategory = "";
    private long quantity;
    private decimal fee = 2.5m;
    private decimal? result;

    protected override void OnParametersSet()
    {
        if (!string.IsNullOrEmpty(selectedCategory) && quantity > 0)
            result = quantity * (1 + fee / 100);
    }
}

💡 Die alten EventCallback-Parameter (OnCategoryChanged, OnQuantityChanged, …) bleiben erhalten – die Komponente kann beide Wege unterstützen.

💡 Tipps

  • @bind-{Property} funktioniert nur, wenn das Child einen EventCallback<T> mit dem Namen {Property}Changed bereitstellt.
  • OnParametersSet wird nach jeder Parameter-Änderung aufgerufen – auch nach @bind-Updates.
  • Du kannst alte (OnCategoryChanged) und neue (SelectedCategoryChanged) Callbacks parallel unterstützen – beide feuern im selben Handler.

✅ Akzeptanzkriterien

  • Parent verwendet @bind-{Property} für alle Child-Komponenten
  • Keine manuellen Handler-Methoden im Parent
  • Berechnung läuft automatisch über OnParametersSet
  • Child-Komponenten stellen zusätzlich {Property}Changed-Callbacks bereit
